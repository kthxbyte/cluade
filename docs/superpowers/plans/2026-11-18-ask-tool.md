# `ask` Tool Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a model-callable `ask` tool so the agent can put a single question — multiple-choice, multi-select, or free text — to the user mid-run and continue with the answer.

**Architecture:** A self-contained executor in `tools.lua` (consistent with every other tool; avoids a `tools→agent` circular dependency), with cooked-tty reads behind overridable seams for testing. `agent.lua` wires it into the normal toolset and excludes it from the unattended `--subagent`/`--plan` toolsets.

**Tech Stack:** Lua 5.1, terminal I/O via `stty … </dev/tty`.

**Spec:** `docs/superpowers/specs/2026-11-18-ask-tool-design.md`

## Global Constraints

- Lua 5.1; terminal only.
- `tools.lua` must not `require("agent")` (circular — `agent.lua` requires `tools.lua`).
- The tool must never block on stdin when there is no user: `--subagent`/`--plan` exclude it from the toolset, and the executor returns an error if reached with no controlling terminal.
- Permission for `ask` is `allow`.
- Existing tests (notably `tests/test_prompt.lua`, `tests/test_subagent_tooling.lua`) stay green.

## Review Focus

- **No controlling terminal:** `execute_ask` returns `{status="error", ...}` and never reads stdin → Task 1 test.
- **Garbage / out-of-range indices** (`"9,foo,1"` for 3 options): invalid tokens ignored, valid ones kept, no crash → Task 1 test.
- **Single-select given several numbers** (`"3,1"`): takes the first only → Task 1 test.
- **"Other" chosen but left blank:** the empty Other is dropped; if nothing else was chosen → `(no answer)` → Task 1 test.
- **Unattended agent cannot call `ask`:** absent from both the `--subagent` and `--plan` toolsets → Task 2 test.

### Task 1: `ask` tool — definition, executor, seams (tools.lua)

**Files:**
- Modify: `tools.lua` — add `DEFS.ask`, `DEFAULT_PERMISSIONS.ask` (`tools.lua:64`), `execute_ask`, the `EXECUTORS.ask` entry (`tools.lua:563`), and the three seams.
- Test: `tests/test_ask.lua`

**Interfaces:**
- Consumes: nothing.
- Produces:
  - `Tools._ask_available() -> boolean` — true when a controlling tty exists (seam).
  - `Tools._ask_write(text)` — write a prompt/body to the user (seam).
  - `Tools._ask_read(prompt) -> string|nil` — cooked-tty line read (seam).
  - `Tools.execute_ask(cwd, params) -> result` where `params = { question, options?, multiple? }` and `result = { status, output }` or `{ status="error", error }`.
  - `DEFS.ask` registered; `EXECUTORS.ask = Tools.execute_ask`; `DEFAULT_PERMISSIONS.ask = "allow"`.

- [ ] **Step 1: Write the failing test** `tests/test_ask.lua`

Stub the three seams; `_ask_read` pops from a queued answer list so sequential reads (selection, then "Other" follow-up) are deterministic.

```lua
-- harness: set Tools._ask_available = function() return true end
-- set answers = {...}; Tools._ask_read = function() return table.remove(answers,1) end
-- Tools._ask_write = function() end

-- missing question -> error
assert(Tools.execute_ask(".", {}).status == "error")

-- no tty -> error, no read attempted
Tools._ask_available = function() return false end
assert(Tools.execute_ask(".", { question = "q", options = {{label="A"}} }).status == "error")
Tools._ask_available = function() return true end

-- single-select by index
answers = { "2" }
assert(Tools.execute_ask(".", { question="pick", options={{label="A"},{label="B"},{label="C"}} }).output == "B")

-- options given as bare strings are normalized
answers = { "1" }
assert(Tools.execute_ask(".", { question="pick", options={"A","B"} }).output == "A")

-- single-select with several numbers -> first only
answers = { "3,1" }
assert(Tools.execute_ask(".", { question="pick", options={{label="A"},{label="B"},{label="C"}} }).output == "A")

-- "Other" (index N+1) -> free-text follow-up
answers = { "4", "custom text" }
assert(Tools.execute_ask(".", { question="pick", options={{label="A"},{label="B"},{label="C"}} }).output == "custom text")

-- multi-select joins labels
answers = { "1,3" }
assert(Tools.execute_ask(".", { question="pick", multiple=true, options={{label="A"},{label="B"},{label="C"}} }).output == "A, C")

-- multi-select with Other appends the typed text
answers = { "2,4", "x" }
assert(Tools.execute_ask(".", { question="pick", multiple=true, options={{label="A"},{label="B"},{label="C"}} }).output == "B, x")

-- garbage/out-of-range tokens ignored
answers = { "9,foo,2" }
assert(Tools.execute_ask(".", { question="pick", options={{label="A"},{label="B"},{label="C"}} }).output == "B")

-- Other chosen but left blank -> dropped -> no answer
answers = { "4", "" }
assert(Tools.execute_ask(".", { question="pick", options={{label="A"},{label="B"},{label="C"}} }).output == "(no answer)")

-- free text (no options)
answers = { "hello world" }
assert(Tools.execute_ask(".", { question="name?" }).output == "hello world")

-- blank answer -> (no answer)
answers = { "" }
assert(Tools.execute_ask(".", { question="pick", options={{label="A"}} }).output == "(no answer)")
```

- [ ] **Step 3: Implement in `tools.lua`**

`DEFS.ask`: schema with `question` (string, required), `options` (array of `{label (string, required), description (string)}`), `multiple` (boolean); description tells the model to omit `options` for a free-text question. `execute_ask`: error if no `question`; error if `not _ask_available()`; normalize `options` (string → `{label=s}`, drop malformed); with options, build a numbered list (`i) label — description`) plus a final `Other` at index `#opts+1`, `_ask_write` it, `_ask_read` one line, collect indices via `line:gmatch("%d+")`, keep `1..#opts+1`; single-select resolves the first index only (Other ⇒ one follow-up read), multi-select resolves all in order (Other ⇒ one follow-up read, appended) and joins labels with `", "`; a blank/empty Other is dropped; no valid selection ⇒ `"(no answer)"`; no options ⇒ one `_ask_read`, returning the text or `"(no answer)"`. Real seams: `_ask_available` probes `stty -g </dev/tty`; `_ask_read` saves/cooks/reads/restores like `Agent:prompt_yes_no`. Register `EXECUTORS.ask` and `DEFAULT_PERMISSIONS.ask = "allow"`.

## Notes for the implementer

- Mirror `Agent:prompt_yes_no` (`agent.lua`) for the real cooked-tty read; do not import it (circular). Duplicating the few `stty` lines in `tools.lua`, or factoring a tiny shared `termio`, are both fine — keep `test_prompt.lua` green and introduce no `tools→agent` require.
- The result `output` is a plain string; it is `json.encode`d into the tool message by the loop, so no special shape is needed.
- Do not add a re-prompt loop: one read per prompt, `(no answer)` on blank/unparseable, and the model may ask again.
